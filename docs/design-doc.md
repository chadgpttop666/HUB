# Личный хаб — диздок

Текстовая копия `Личный хаб — диздок.pdf` (20 ноября 2026). Схемы из PDF пересказаны списками.

## Что это и зачем

Хаб — одно приложение для ПК и телефона, которое собирает личные инструменты (повторение, корзину идей, календарь, дневник) в одном месте. У них общие данные, общая тема и синхронизация через свой Google Drive, без собственного сервера.

Сейчас эти инструменты разрозненные, часть недоделана, синхронизация между устройствами работает плохо. Хаб должен стать местом, куда новый инструмент добавляется за вечер, а не отдельным проектом с нуля.

## Цели первой версии

- Включил компьютер — хаб открылся сам: приветственный экран и все приложения в одном меню.
- Любая мысль за пару секунд падает в корзину, потом разбирается по приложениям.
- Новое приложение ставится без переделки хаба: нейронка пишет его по файлу правил, его папка или архив устанавливается в хаб.
- Помеченные папки, включая хранилище Obsidian, одинаковы на ПК и телефоне.
- Всё, что лежит на Drive, зашифровано; данные хаба на устройстве открываются только после пароля.

## Не цели первой версии

- Каталог приложений и чужие пользователи — только когда хаб приживётся у самого автора.
- Свой сервер.
- Совместная работа в реальном времени.
- Перетаскиваемая раскладка и виджеты на главном экране.

## Принципы

1. **Не монолит.** Хаб — оболочка, вся полезная работа в отдельных приложениях. Удалил приложение — хаб и остальные приложения работают как раньше.
2. **Узкий контракт.** Приложение видит только Hub API. Чем меньше в нём функций, тем надёжнее нейронка пишет приложения по файлу правил.
3. **Данные принадлежат мне.** Всё хранится на моих устройствах и на моём Google Drive, в открытых форматах. Если хаб сломается, данные достаются обычными инструментами (rclone).
4. **Без своего сервера.** Облако — только хранилище файлов, вся логика на устройствах.
5. **Работает без интернета.** Локальная база главная, Drive догоняет её, когда появится связь.
6. **Безопасно по умолчанию.** В облако уходит только зашифрованное. Приложения изолированы друг от друга и от ключей.
7. **Сначала пользоваться, потом расширять.** Каждый этап заканчивается тем, что хабом пользуются в жизни, а не тем, что дописана новая функция.

## Архитектура

Схема «Приложения видят только Hub API, а ключи и Drive — только ядро»:

- **Оболочка хаба** (темы · быстрый ввод · меню · замок): Повторение (песочница iframe), Корзина GTD (встроена в хаб), Календарь (песочница iframe), Приложение N (по APP_SPEC.md).
- **Hub API**: данные, корзина, тема, уведомления — единственный выход приложений.
- **Ядро на Rust** — только оно видит ключи, файлы и Drive:
  - зашифрованная база — данные хаба и приложений, открыта только после пароля;
  - синхронизация — rclone bisync + crypt, журналы, снимки, стоп-кран;
  - ключи — пароль → ключ данных, ключ восстановления на бумаге.
- **Помеченные папки** — Obsidian и другие, с меткой `.hubsync`, на диске лежат открытыми.
- **Google Drive** — только зашифрованное: файлы папок, журналы устройств, снимки.

Приложения живут в песочницах и общаются только с Hub API. Ядро держит ключи, шифрует базу и через rclone синхронизирует помеченные папки с Drive. Новое приложение автоматически получает синхронизацию и шифрование, ничего для этого не пиша.

## Приложения

Приложение — это папка с манифестом и веб-страницей, которую хаб открывает в песочнице. Одно и то же приложение работает и на ПК, и на телефоне.

Состав папки:

```
repetition/
  manifest.json   — имя, версия, иконка, права, что принимает из корзины
  index.html      — само приложение
  icon.svg
```

Что приложение может через Hub API:

- Хранить свои данные: записать, прочитать, удалить. Видит только свои данные, чужие ему недоступны.
- Положить элемент в корзину и принять элемент из неё.
- Получить тему и узнать, что она сменилась.
- Показать уведомление.

Больше ничего: к Drive, к файлам на диске и к сети приложение само не ходит. Нужен доступ к сети — он заявляется в манифесте, и хаб спрашивает разрешение при установке.

**Установка.** Перетащить папку или zip-архив в хаб → хаб показывает имя и запрошенные права → подтверждение → приложение появляется в меню. Установленные приложения синхронизируются на телефон вместе с данными.

**Файл правил для нейронки (`APP_SPEC.md`).** Один файл, который прикладывается к запросу «сделай мне приложение для…». В нём:

- формат манифеста с примером;
- все функции Hub API с примерами вызова;
- список CSS-переменных темы, которые обязательно использовать вместо своих цветов;
- запреты: не грузить скрипты из интернета без заявки, не хранить данные мимо Hub API;
- готовый шаблон минимального приложения, которое заведомо работает.

### Первые приложения

| Приложение | Откуда | Этап |
| --- | --- | --- |
| Повторение (теории, FSRS, план, дневник) | перенос repetition.html | 1 |
| Корзина GTD | новое, встроено в хаб | 1 |
| Календарь | новое, пишет нейронка по APP_SPEC.md | 3 |

**Перенос repetition.html.** Сейчас оно хранит данные в localStorage, а в песочнице localStorage недоступен. Обвязка хаба его подменяет: при запуске отдаёт приложению все его данные, чтение идёт из памяти, запись в фоне уходит в хаб. Старые данные импортируются один раз. Получится ли обойтись парой строк, проверяется на первом этапе (уверенность средняя).

## Корзина GTD

Корзина встроена в сам хаб: строка ввода всегда в шапке и по горячей клавише, а куда разбирать элементы, решают приложения.

1. **Захват.** Написал мысль, нажал Enter — она в корзине. Никаких полей и вопросов на этом шаге.
2. **Разбор.** У каждого элемента кнопка «перенести в…» и перетаскивание на иконку приложения. Там же «удалить» и «отложить».
3. **Приём.** Приложение-получатель забирает элемент и само решает, чем он станет: карточкой, событием, записью. Из корзины элемент уходит.

Как приложение попадает в список «перенести в…» — оно объявляет в манифесте, что принимает:

```json
"accepts": [
  { "type": "text", "label": "Карточка для повторения" },
  { "type": "task", "label": "Задача с датой" }
]
```

Поставил новое приложение — оно само появилось в списке. Удалил — исчезло, корзина при этом не ломается.

Элемент корзины: текст, время создания, устройство, необязательные метки. Корзина синхронизируется как и всё остальное: что кинул с телефона, разбираешь на ПК.

## Темы и кастомизация

Тема — набор CSS-переменных, который хаб передаёт во все приложения, поэтому одна тема перекрашивает всё сразу.

```
--bg; --surface; --text; --text-muted; --accent; --danger;
--radius; --font-body; --font-heading; --font-size-base;
```

Тема — файл `theme.json` с этими значениями, плюс картинка приветственного экрана. Темы тоже синхронизируются; тему можно попросить у нейронки так же, как приложение.

| В первой версии | Отложено |
| --- | --- |
| цвета, шрифты, скругления | перетаскиваемая раскладка главного экрана |
| светлая и тёмная тема | виджеты приложений на главном экране |
| картинка и текст приветствия | свои стили для отдельных приложений |
| порядок приложений в меню | анимации и звуки |

## Синхронизация

Синхронизируется любая помеченная папка, по файлам, через rclone bisync в зашифрованную папку на моём Google Drive. Собственные данные хаба — такая же папка.

**Метка.** «Синхронизировать папку» → выбрать папку → хаб кладёт в неё `.hubsync`:

```json
{ "id": "obsidian-main", "mode": "two-way", "encrypt": true, "exclude": [".obsidian/workspace*.json"] }
```

Метка переезжает вместе с папкой. На втором устройстве хаб видит новую папку на Drive и спрашивает, куда её положить. Диск в поисках меток хаб не сканирует, а помнит список своих папок.

Режимы: в обе стороны (по умолчанию) или только копия в облако.

**Почему по файлам, а не архивом**

| | Один зашифрованный архив | Каждый файл отдельно (выбрано) |
| --- | --- | --- |
| Что видит Google | один непонятный файл | число файлов и их размеры, не имена и не содержимое |
| Поменялась одна заметка | заново грузится весь архив | грузится одна заметка |
| На двух устройствах правили разные файлы | один архив затирает другой | сливается само |

**Конфликты.** Если один и тот же файл изменён на двух устройствах, сохраняются обе версии, и хаб показывает конфликт для ручного выбора. Молча ничего не затирается.

**Данные самого хаба.** Каждое устройство пишет только свой журнал изменений (`changes-pc`, `changes-phone`) и читает чужие. В каждый файл пишет одно устройство, поэтому файлы не конфликтуют. Правка хранит сведения о версиях записи, известных её автору. Независимые правки сохраняются до ручного выбора в настройках, а правка на основе известной версии её заменяет. Журналы время от времени сворачиваются в снимок.

**Когда идёт синхронизация:** при открытии хаба, после изменений (с паузой в несколько секунд), по кнопке и, где система позволяет, в фоне по расписанию.

**Страховка**

- Стоп-кран bisync против массового удаления включён всегда (точный порог — проверить).
- Ежедневный зашифрованный архив-снимок каждой папки, последние 30 снимков.
- Перед первой синхронизацией папки — пробный прогон: хаб показывает, что собирается сделать.

## Шифрование и безопасность

Замков два. На Drive зашифровано всё и всегда. На устройстве до ввода пароля закрыты данные хаба, но не папки, с которыми работают другие программы.

**Замок 1 — облако.** Файлы шифруются на устройстве до отправки, в формате rclone crypt: содержимое — XSalsa20-Poly1305, имена файлов — AES-EME. Ключ есть только на моих устройствах.

**Замок 2 — устройство.** База хаба (корзина, повторение, календарь) лежит зашифрованной и расшифровывается в памяти после ввода пароля. После N минут бездействия хаб снова запирается. Папки вроде хранилища Obsidian лежат на диске открытыми, иначе Obsidian не сможет их прочитать. Их защищает шифрование диска системой: BitLocker на ПК, встроенное шифрование на телефоне.

**Ключи**

1. Данные шифруются случайным ключом данных.
2. Ключ данных заперт ключом из пароля (Argon2id). Смена пароля перезаписывает один маленький файл, а не все данные.
3. Тот же ключ данных заперт ещё и ключом восстановления, который печатается или записывается на бумагу при настройке. Забыл пароль и потерял бумагу — данных нет навсегда.
4. Пароль для rclone не лежит в его файле настроек: там он только замаскирован, и маскировка снимается за секунду. Хаб передаёт ключ rclone только в памяти, или файл настроек целиком запирается паролем.

**От чего защищает**

| Угроза | Защита |
| --- | --- |
| Google или кто-то с доступом к аккаунту читает файлы | замок 1 |
| Кто-то сел за включённый ПК и открыл хаб | замок 2 и автоблокировка |
| Украли выключенный ноутбук или телефон | шифрование диска системой |
| Чужое приложение в хабе пытается украсть данные | песочница и права из манифеста |
| Ошибка синхронизации удалила файлы везде | стоп-кран и снимки |
| Украли ключ доступа к Drive | данные не прочитать; удалить можно, от этого спасают снимки; у хаба права только на свою папку |

**Что не закрыто:** Google видит, сколько файлов и какого они размера; на разблокированном устройстве с вирусом защиты нет. rclone скачивается только с официального сайта и обновляется.

## Платформы и стек

Хаб — нативное приложение на Tauri 2. Ядро на Rust отвечает за файлы, шифрование, вход в Google и запуск rclone. Интерфейс и приложения — веб-страницы.

**Почему приложения остаются веб-страницами.** Нейронка лучше всего пишет именно их, и одно приложение работает на всех платформах. Obsidian устроен так же: сам он программа, а плагины — JavaScript.

| Платформа | Как работает | Ограничения |
| --- | --- | --- |
| ПК (Windows) | rclone.exe лежит внутри хаба, хаб запускает его в фоне; автозапуск при входе в систему с приветственным экраном | нет |
| Android | rclone встроен как библиотека (так делает Round Sync); доступ к папке Obsidian через системный выбор папки; фоновая синхронизация по расписанию | файловая система Android строгая; фон, скорее всего, дописывается на Kotlin; зрелость Tauri на телефонах — уверенность средняя |
| iPhone | доступ к папке Obsidian через «Файлы», кажется, возможен; синхронизация при открытии хаба | фона почти нет, rclone встроить тяжело — уверенность низкая, нужна проверка |

**Вход в Google.** Нужен свой проект в Google Cloud и ключ для входа. Права узкие: хаб видит только файлы, которые создал сам. Для чужих пользователей позже понадобится проверка приложения в Google.

## План этапов

Следующий этап начинается, только когда предыдущим реально пользуются.

| Этап | Что | Критерий перехода к следующему |
| --- | --- | --- |
| 0. Проверка rclone | тестовая папка: синхронизация, шифрование, конфликт, удаление | rclone ведёт себя как ожидалось — берём его движком |
| 1. Оболочка, корзина, повторение | только ПК, без синхронизации; перенос repetition.html | две недели реально пользуюсь корзиной и повторением |
| 2. Синхронизация и телефон | rclone + шифрование, Drive, Obsidian, ключ восстановления | две недели на ПК и телефоне без потерянных изменений |
| 3. Приложения от нейронки | APP_SPEC.md, установка из папки или zip, календарь | календарь от нейронки работает без правок хаба |
| 4. Темы и приветствие | темы, приветственный экран, автозапуск при входе в систему | хаб прижился: открываю его каждый день |
| 5. Чужие пользователи | каталог приложений, проверка приложения в Google | — |

Сроков нет намеренно: этап считается закрытым, когда выполнен критерий перехода, а не когда дописан код.

## Риски и открытые вопросы

Главный риск не технический: построить платформу и не пользоваться ею. Поэтому каждый этап заканчивается использованием, а каталог для чужих пользователей стоит в самом конце.

| Риск | Что делаем |
| --- | --- |
| Синхронизация теряет файлы | готовый rclone вместо своего движка, стоп-кран, снимки, пробный прогон |
| Забытый пароль | ключ восстановления на бумаге с первого дня |
| Tauri на телефоне окажется сырым | прототип на телефоне до основной работы; запасной вариант — отдельное нативное приложение для телефона |
| Перенос repetition.html сложнее, чем казалось | проверить первым делом на этапе 1 |
| Google ограничит вход (в тестовом режиме вход, кажется, слетает раз в неделю) | проверить на этапе 2; при необходимости перевести проект Google Cloud из тестового режима |
| Round Sync и другие обёртки rclone для Android заброшены | сам rclone живой; встраиваем его сами, Round Sync — лишь пример, что это возможно |

**Открытые вопросы**

- Телефон: Android или iPhone? От этого зависит этап 2.
- Какие папки, кроме данных хаба и хранилища Obsidian, синхронизировать?
- Через сколько минут бездействия запирать хаб?
- Календарь свой или поверх Google Календаря?
- Порог стоп-крана bisync — сверить с документацией rclone.
