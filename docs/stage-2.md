# Этап 0 и этап 2: rclone, шифрование, синхронизация, телефон

Критерий перехода к этапу 3 (из диздока): **две недели на ПК и телефоне без потерянных изменений**.

Решения по открытым вопросам диздока: телефон — **Android**; автозамок — **15 минут** (меняется в «Настройках»); порог стоп-крана — ниже.

## Этап 0: проверка rclone

`tools/rclone-check/check.sh` — 17 проверок на rclone 1.76.0, «Drive» изображает папка (логика bisync и crypt от хранилища не зависит). Всё в порядке:

- crypt: на «диске» нет ни открытых имён, ни открытого текста; rclone читает обратно;
- bisync: правки в разных файлах на двух устройствах сливаются сами, удаление доходит;
- один файл правили на обоих — **сохраняются обе версии** (`заметка.md.sync-conflict1`, `…2`), исходное имя не занято молча;
- **стоп-кран**: bisync по умолчанию отказывается, если на одной стороне удалено **больше 50 %** файлов (`Safety abort: too many deletes (>50%, 8 of 13)`); `--max-delete N` задаёт порог в процентах. После отказа `--resync` возвращает файлы с другой стороны, ничего не удаляя.

Вывод: rclone берём движком, как и планировалось. Скрипт гоняется в CI на каждой сборке.

## Замок 2: пароль и шифрование на устройстве

- **Ключ данных** — 32 случайных байта. Каждый файл данных зашифрован им (XChaCha20-Poly1305, `src-tauri/src/crypto.rs`).
- Ключ данных заперт **паролем** (Argon2id, 64 МБ, 3 прохода) и **ключом восстановления** (32 знака, 8 групп по 4, без похожих букв) — `keys.json` рядом с данными. Смена пароля перезаписывает только `keys.json`.
- До ввода пароля ядро не читает ни одного файла данных. **Замок** (`Ctrl+L`, кнопка, 15 минут без дела) выгружает из памяти и данные, и страницы приложений.
- Первая настройка: имя → пароль дважды → ключ восстановления (печать, отметка «записал») → Google Drive или «позже». Данные этапа 1 при этом шифруются на месте.
- Вход: экран с часами, любая клавиша — поле пароля; неверный пароль — поле вздрагивает, подсказка про английскую раскладку и Caps Lock, ссылка «Войти ключом восстановления» (ключ + новый пароль).

## Замок 1 и синхронизация

**Раскладка на Drive** (права `drive.file` — хаб видит только свои файлы):

```
Hub/keys.json         запертый ключ данных — без пароля бесполезен
Hub/crypt/…           rclone crypt: имена AES-EME, содержимое XSalsa20-Poly1305
  hub/changes-<устройство>/<номер>.json    журналы изменений
  hub/blobs/<sha256>                        двоичные значения (фото, ролики)
  folders/<id>/…                            помеченные папки
  snapshots/<id>/<дата>/…                   ежедневные снимки, 30 последних
```

Пароли crypt выводятся из ключа данных и передаются rclone только переменными окружения; файла настроек rclone нет. Достать данные без хаба: «Настройки → Синхронизация → Пароли для rclone» (после пароля хаба) и обычный rclone.

**Данные хаба и приложений — журналами.** Каждое устройство пишет только свой журнал и читает чужие. Запись — «ключ стал таким-то в момент ts». Корзина и доставки хранятся по ключу на элемент, поэтому мысли с двух устройств просто складываются. Если один ключ правили на обоих (например, вся база «Повторения» — один ключ), остаётся более поздняя правка, а **проигравшая версия сохраняется** и видна в «Настройках → Конфликты данных» с кнопкой «Вернуть эту». Пришедшие изменения хаб применяет сразу; открытое приложение перезапускается с уведомлением, чтобы не записать поверх устаревшую копию.

**Помеченные папки** — `rclone bisync` между папкой и `folders/<id>`. «Синхронизировать папку» кладёт в неё `.hubsync`, описание папки уходит в данные хаба — второе устройство его видит и спрашивает, куда положить. Перед первой синхронизацией — **пробный прогон** (что уйдёт, что придёт, что различается). Стоп-кран (больше 50 % удалений) останавливает папку и предлагает «Вернуть файлы» или «Удалить везде». Конфликты — список файлов с «Оставить эту». Режим «только копия в облако» есть в ядре, в интерфейсе пока не выбирается.

**Когда:** при входе, через 4 с после правок, раз в 5 минут, по кнопке; без сети — повтор раз в минуту, статус «нет сети · всё сохранено здесь».

**Google:** вход через `rclone authorize` в браузере. Свой проект Google Cloud необязателен (поля «Client ID / secret» в настройках); без него — общий ключ rclone с общими лимитами Google.

## Телефон (Android)

- Тот же хаб: Tauri 2, тот же интерфейс в телефонной раскладке (нижняя панель «Сегодня / Корзина / Приложения / Настройки», приложение во весь экран со стрелкой «назад», системная кнопка «назад» работает через историю, «Отложить до» — нижним листом).
- rclone собирается из исходников под Android (Go + NDK, `scripts/build-rclone-android.sh`) и лежит в APK как `librclone.so`: запускать программы Android разрешает только из папки библиотек приложения.
- Подключение: на телефоне «Подключить к существующему» → вход в Google → пароль хаба. Ключи и данные приходят с Drive.
- Папка Obsidian: указывается полным путём (`/storage/emulated/0/Documents/Obsidian`); нужно разрешение «Доступ ко всем файлам» (Настройки Android → Приложения → Хаб).
- APK — артефакт **hub-android** в Actions. Подписывается постоянным ключом: без этого обновление не встанет поверх и придётся удалять приложение вместе с данными. Сейчас ключ живёт в кэше CI; надёжнее положить его в секреты репозитория — см. ниже.

## Что не проверено и где я не уверен

- **Настоящий Google Drive не подключался ни разу** — здесь нет аккаунта. Проверены: формирование ссылки входа (`drive.file`, адрес возврата 127.0.0.1:53682) и вся логика на папке вместо Drive. Не проверено: что rclone с настройками только в памяти спокойно продлевает токен Google (уверенность средняя — он может ругаться, что не может сохранить настройки, но работать); что вход в Google открывается в браузере на Windows (уверенность высокая) и на Android (средняя).
- **Android вживую не запускался** — только сборка APK в CI. Самые сомнительные места: запуск `librclone.so` из папки библиотек (так делают Termux и Round Sync — уверенность средняя), вход в Google на телефоне (браузер должен вернуться на 127.0.0.1, пока хаб в фоне — средняя), «Доступ ко всем файлам» для папки Obsidian (средняя). Если вход в Google на телефоне не пройдёт — запасной путь пока не сделан (перенести токен с ПК).
- **Фоновой синхронизации на телефоне нет**: только пока хаб открыт. Диздок ожидал, что фон придётся дописывать на Kotlin, — это следующий шаг.
- **Виджет и «Поделиться → Хаб» на Android** не сделаны.
- **Windows (WebView2)** — установщик собирается в CI, вживую не запускался. Первым делом стоит поставить `tools/sandbox-probe` (см. stage-1.md) и проверить вход в Google.
- Спор «последняя правка побеждает» для «Повторения» грубый: база целиком — один ключ, поэтому правки с двух устройств в один промежуток не сольются, а одна уйдёт в конфликты (с кнопкой «Вернуть эту»). Чтобы сливалось по записям, «Повторению» нужно хранить записи отдельными ключами через `hub.data` — это его переделка, а не хаба.
- Журналы пока не сворачиваются в снимок: новое устройство читает их с начала. На месяцы личного пользования хватит; сворачивание — когда понадобится.
- Порядок времени между устройствами берётся по их часам. Если часы телефона сильно убегут, «последняя» правка может оказаться не той — проигравшая всё равно сохранится в конфликтах.

## Постоянный ключ подписи APK (один раз)

```bash
keytool -genkeypair -keystore hub.jks -alias hub -keyalg RSA -keysize 3072 -validity 20000 -dname "CN=Hub"
```

```bash
base64 -w0 hub.jks
```

Вывод — в секрет репозитория `ANDROID_KEYSTORE_BASE64`, пароль — в `ANDROID_KEYSTORE_PASSWORD` (Settings → Secrets and variables → Actions). Сам `hub.jks` — сохранить где-нибудь, кроме репозитория.
